Every surface, and how far it goes.

Rigel is six working surfaces sharing one project database. Each page below covers the mechanics, the failure modes and the commands, and says which parts are exercised by tests and which are not.

The surfaces

Sessions

A roster of agents, a transcript that keeps roles and tools apart, and a resume that reconciles the journal instead of replaying it.

Open the sessions page

Claims and merge

Claims are advisory, a watcher attributes every write, and a collision opens base, ours and theirs instead of refusing the second writer.

Open the claims page

Budget and safety

Micro-dollar accounting per turn and per child, a preflight estimate, an 80% warning and a daily cap that stops the next turn before it starts.

Open the budget page

Skill shelf

An offline FTS5 index with SimHash duplicates, six capability rules with file:line evidence, and source health read without a network call.

Open the shelf page

Terminal

A real PTY in the project root, plus the command gate that names the text, cwd and timeout before anything runs.

Open the terminal page

Cloud and phone

Your own Firebase project, opt-in shelf metadata, tombstones, and one published session readable on an iPhone.

Open the cloud page

State, without rounding up

The repository keeps one table of what works and how it was verified. These are its states, not marketing tiers: real means exercised by the build or its tests, protocol means verified against a scripted implementation because the vendor CLI is not installed on the build machine, and not ported means the surface does not exist yet.

Surface State What backs it
Sessions real Roster, transcript, outline, bookmarks, templates, resume; a keyboard-only exit walk is still open.
Claims real Acquire, heartbeat, release, tombstones, staleness, 24 h expiry.
Patches real CAS check, write-ahead journal, fsync and rename, idempotent apply, one revert.
Bill and cap real Per-turn and per-child usage, local price fallback, daily cap, reconcile.
Skill shelf real SQLite FTS5, six capability rules, SimHash clusters, ETag source sync.
Terminal real portable-pty, PowerShell or $SHELL, xterm.js, live settings.
Cloud real, opt-in Exercised against a local stand-in for the Firebase hosts; no live project is owned by the repository.
Phone reader real Signs in to the same project and decodes the published turns.
Discover, Targets, Dependencies not ported Still the Phase 0 browser app.

What is deliberately unfinished

The gaps are part of the design record, so they get the same space as the features:

  • A keyboard-only walk of the full exit test on a real build is open. Focus order, reduced motion and a high-contrast palette are implemented, but that walk is the remaining proof.
  • The Claude harness answers a live turn with --mcp-config and the approval tool, but the repository has only run it against a scripted stream, not a live subscription.
  • Muse Code, Gemini CLI, Cursor and Cline are verified against scripted implementations. None of those CLIs is installed on the build machine.
  • Cloud is exercised end to end against a local stand-in for all three Firebase hosts. It has not been run against a live Firebase project owned by the repository.

How to read a claim here

A page will say real and name the mechanism, or it will say protocol and name the scripted implementation. If a sentence has no mechanism behind it, it does not belong on these pages. The what-works table is the authority when a page and the table disagree.

The CLI side of every surface is documented with its exit codes in the repository. Commands shown on these pages are the ones that exist today, not planned flags.

A real shell, with a gate.

The terminal is a PTY in the project root, not a text box pretending to be one. Agents reach the same surface through a command tool that shows the exact command, working directory and timeout before anything executes.

A real PTY

The rail surface is backed by portable-pty, opened in the project root. PowerShell is the shipped Windows shell; elsewhere Rigel reads $SHELL. xterm.js handles drawing and keys, while input, output and resizes cross IPC to the core.

The surface is framed as a canvas with a status pane: shell, cwd, state and font size. The status pane is the answer to “which shell is this, and where is it”, which a bare prompt only implies.

Font, scrollback, shell

Settings → Terminal holds three controls. The first two apply to an open tab in place; the third is read when a tab opens.

Setting Range When it applies
Font size 10 to 20 px Immediately, without restarting the PTY.
Scrollback 1,000 to 100,000 lines Immediately, without restarting the PTY.
Shell program An executable path The next tab; an open shell keeps its own program.

Restart opens a fresh shell on purpose. It is not a reconnect to the old process, because a restarted shell that silently inherited state would be harder to reason about.

The command gate

run_command is one of the native agent’s tools. Its approval card shows the exact command text, the cwd and the timeout before the process starts. Approvals have the same four scopes as the CLI: once, session, always and deny.

  • The cwd is jailed to the project. A path outside it is refused by the tool.
  • Each stream is capped at 64 KB; the cap is recorded, not silently exceeded.
  • The process is killed at its timeout, and the exit code is recorded as a command item on the turn.
  • --approval ask|allow|deny sets the policy for a CLI run; with --json, the default is deny.

Destructive commands

A deterministic classifier runs before approval. It maps the command to policy rows: delete-outside-project, recursive-remove, force-push, git-reset and registry-write. The prompt names both the row and the token that matched it.

A destructive command also gets one round of three read-only advisors on the parent’s model: advocate, opponent and referee. Their answers are shown before the question is asked. They are advisory and cannot allow, deny or alter the gate.

If you approve, Rigel captures a snapshot first: a git stash create object kept alive by refs/rigel/snapshots/<id> plus raw copies of changed and untracked files. Non-git trees are copied whole. The cap is 2,000 files or 200 MB, and the capture refuses above it rather than truncating.

The claims page covers what happens to the snapshot afterwards and how a restore is journaled.

Tabs, tray, lifetime

The shell survives tab switches. Closing the window hides it in the tray with the agents and PTYs still running; the tray reopens the window or quits and reaps every child. If the tray cannot be built, Close keeps its ordinary meaning.

Console children spawned by turns and probes are hidden on Windows, so a command never flashes a black window. The chat server runs under pythonw.exe for the same reason.

Limits

  • The gate is approval policy, not an OS sandbox. An approved command runs with your user’s rights; only the cwd jail applies to Rigel’s own tool call.
  • Output is capped at 64 KB per stream. The full output is not kept elsewhere.
  • A shell program change does not migrate the open PTY; it applies to the next tab.
  • Windows is the supported desktop surface. $SHELL exists for the core, not as a promise of a supported desktop build.

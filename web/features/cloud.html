Your cloud, your reader.

Rigel Cloud is opt-in and runs in a Firebase project you own. Push mirrors shelf metadata, Publish writes one session’s prompts and replies to your phone, and the web reader is read-only. Bodies, tool output and project paths stay on the desktop.

Ownership

There is no Rigel subscription and no Rigel-hosted tenant database. You point the app at a Firebase project you own; the bill, the rules and the data are yours. If you never configure it, the cloud surface stays absent and the local app is unchanged.

The repository exercises the whole flow against a local stand-in for the Firebase hosts. It does not ship a live project of its own, which is why this page says “opt-in” rather than "hosted".

The account

Identity Toolkit email/password sign-in is the account path: sign in, create an account, reset a password and verify an email. The account page carries a send/resend control for verification, and rigel cloud verify --check answers the same question from the CLI.

  • The refresh token and the verification answer live in the OS keychain, never in the renderer.
  • A reset answer does not reveal whether the account exists.
  • Signing out removes the local credential; it does not delete the project’s data.

Push, pull, tombstones

Push and Pull mirror shelf metadata through Firestore REST under per-user rules. A skill body stays on the machine that fetched it. A deletion travels as a tombstone from a per-account manifest, cloud-state.json, so a pull does not resurrect a row that was deliberately removed.

Settings → Cloud shows the last push and last pull clock; rigel cloud status prints the same state. The clock is the answer to "is this machine up to date", not a progress animation.

Publish to the phone

Publish writes one session’s turns to users/{uid}/sessions/{id}/turns. Each turn keeps the prompt and the assistant’s own text. It deliberately excludes:

  • Tool calls and their arguments.
  • Command output.
  • The project path.

The iPhone client signs in to the same project and lists and reads those documents. Its decoder is covered by the phone’s CloudKit tests. The desktop owns the shelf, the agents and the transcripts; the phone is a reader.

This is the same data the web reader at /app/ reads in a browser, scoped by the same rules.

App Check

Optional Firebase App Check runs through a custom provider shipped in functions/. The provider verifies a per-install client token in constant time, rate-limits each installation and address with Firestore token buckets, and mints tokens with the Admin SDK.

Configure it with rigel cloud app-check --url and --client-token, or from Settings → Cloud. The endpoint and the client token are stored where the other cloud settings live; the client token stays in the OS keychain. Tokens are cached in memory and attached as X-Firebase-AppCheck to every Firebase request.

The provider’s contract is explicit: a token, a Unix-second expiry, and fail-closed errors. A provider that cannot answer does not degrade into an open door.

The web reader

The web app is a separate static surface at /app/. It signs in with the same account, lists the sessions you published, and renders titles, projects, prompts and replies. It is not a second control surface: it cannot run an agent, take a claim or change a setting.

Firestore rules only let a signed-in account read its own documents. The reader’s UI says so, and the rules are the part that enforces it.

The cloud CLI

Command Does
rigel cloud status Shows the configured project, account, clocks and App Check state.
rigel cloud configure Stores the project and web API key.
rigel cloud login Signs in and keeps the refresh token in the keychain.
rigel cloud sign-up Creates an account in the configured project.
rigel cloud reset Sends a password reset without revealing whether the account exists.
rigel cloud logout Removes the local credential.
rigel cloud push Mirrors shelf metadata up, with tombstones.
rigel cloud pull Mirrors shelf metadata down.
rigel cloud sync Push then pull, with the clocks recorded.
rigel cloud publish Writes one session’s prompts and replies for the readers.
rigel cloud app-check Stores the App Check endpoint and client token.

Every command accepts --json. The password and the web API key are read from stdin; they are not accepted as command-line arguments.

Limits

  • The repository has exercised cloud against a local Firebase stand-in, not a live project it owns.
  • You own the Firebase project, its rules, its quotas and its bill.
  • Push is metadata only. It is not a backup of bodies, patches or transcripts.
  • Publish sends one session at a time and excludes tool calls, output and paths.
  • The readers are read-only. There is no phone-side agent control.
  • The phone client is iOS. There is no Android client in this repository.

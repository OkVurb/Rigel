An index you can audit.

The shelf is a local SQLite index of agent skills, built from sources you point it at. It searches offline, clusters near-copies, reviews what it fetched, and keeps the difference between what a skill advertises and what Rigel actually measured.

A local corpus

Skill bodies live in a blob store beside an FTS5 index in index.db. Search, the row list and the opened detail all read that one database; no query leaves the machine. The shelf is usable with the network unplugged, which is also the state the screenshots are captured in.

A fetched body is cached with its source and content hash. The next sync can ask whether the source changed instead of downloading every body again.

Where rows come from

Source What Rigel keeps
GitHub An owner/repo or any GitHub URL, one tree call, raw bodies and an ETag cache.
SkillsMP and SkillHub Metadata only, because those sources do not publish bodies. A row without a body cannot receive a static review.
skills.sh page That one skill’s body, plus the page’s Gen, Socket and Snyk verdicts as dated evidence rows.
Prototype export An explicit import from the Phase 0 index, not a silent migration.

The importer refuses a skills.sh page that has no audit section instead of reading the absence as a pass. A verdict never changes Rigel’s own grade; it is stored beside it as dated third-party evidence.

Duplicates

After every ingest, SimHash clusters near-copies at a Hamming distance of three bits or less. Twenty forks of one prompt become one row with a variant list, not twenty search results. The cluster is recomputed after each ingest, so a new fork joins the row instead of creating a second one.

The variant list is not a delete pile. Each variant keeps its source and evidence; the cluster is a reading aid.

The static review

Six capability rules scan a fetched body and flag privilege escalation, network egress, destructive commands and related capabilities. Every hit carries the file:line that triggered it, so the review can be checked rather than trusted. The grade comes from the same scan the prototype used, which makes the two comparable.

Source health is separate from the grade: ok, stale with the last-sync date, or broken. All three are read without a network call. A broken source is a fact about the source, not a verdict on the skill.

Reading a grade: it says what the six rules covered, not that the skill is safe. A row with no body says it could not be reviewed, rather than showing a green score it did not earn.

Checking a skill

The six rules are one layer, not a safety proof. The repository also carries an OWASP review skill built from the Agentic Skills Top 10. It returns a per-risk verdict with file:line evidence, and leaves a risk unchecked when the reviewer did not look.

For a second, independent pass, NVIDIA SkillSpector is an Apache-2.0 scanner for skill directories, repositories, archives and single files. Its static pass needs no API key; the optional semantic pass does. It can emit SARIF for CI instead of a terminal report. 

uv tool install git+https://github.com/NVIDIA/SkillSpector.git
skillspector scan ./my-skill --no-llm --format sarif --output skillspector.sarif

The layers answer different questions. The local rules say what Rigel measured; the OWASP review says what a reader checked; SkillSpector adds its own patterns and, when enabled, a model's reading. None of them proves a skill harmless, and none of them is run silently by the shelf.

Advertised, measured, audited

A skill’s description often carries a percentage. Rigel records it as advertised and marks the row unmeasured until a measurement exists. A dated third-party verdict is recorded as audited, with the date and the auditor. The three are never flattened into one number.

The shelf also counts what it holds, and the number is deliberately unglamorous: the catalogue carries 11,587 skills measured from public sources. Independent censuses put the entire public universe at roughly 238,000 unique skills, so a claim of 300,000 would be padding rather than coverage.

Freshness

At launch, a source older than the stale window is re-synced off the UI thread, unless the auto-refresh switch is off. Settings → Skill shelf lists each source, refreshes on demand and indexes a repository. rigel skills refresh is the same pass, and the two faces share one implementation.

An empty shelf offers “Index repository” when no source has ever synced, instead of showing a blank table with no next step.

The CLI

Every shelf command returns JSON on request and follows the repository’s exit codes, so the terminal is a first-class surface rather than a debug console.

Command Does
rigel skills index Crawls a source, stores bodies and builds the FTS5 rows.
rigel skills search Full-text search over the local index.
rigel skills get Prints one row with its grade, health and evidence.
rigel skills status Shows sources, freshness and index counts.
rigel skills sync Refreshes the marketplace sources that publish metadata.
rigel skills sweep Re-runs the static review over the corpus.
rigel skills stats Prints corpus counts and cluster totals.
rigel skills import Imports a prototype export or one skills.sh page.
rigel skills gc Removes unreferenced blobs.
rigel skills refresh The same refresh pass the window runs.
rigel trust explain Prints the five-factor arithmetic behind a tool’s trust decision. 
rigel skills index anthropics/skills --limit 20
rigel skills search "pdf" --json
rigel skills sweep
rigel doctor

Limits

  • A metadata-only source cannot be reviewed. Its rows say so.
  • The six rules are static. A body that fetches something at run time is not exercised by the scan.
  • SimHash is a near-copy detector, not a plagiarism ruling; the variants stay available.
  • The catalogue count tracks what was indexed, so it moves between releases.
  • Refresh needs the network. The index and the review do not.

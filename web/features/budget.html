The bill, before and after.

Rigel records provider usage per turn, prices it in micro-dollars, warns at 80% of the day’s cap and refuses the next turn when the cap is reached. Nothing about the bill depends on the window staying open.

Accounting

Every turn writes a usage row: provider, model, input and output tokens where the provider reports them, and a micro-dollar cost. The price comes from the provider’s usage answer when it carries one, and from the local price table when it does not. A missing price is recorded as an estimate, not silently multiplied into a confident total.

The ledger is per project. Switching projects switches the bill, because the spend belongs to the work, not to the window.

Per agent, per child

A fan-out is not one number. Each child agent is its own agent row and its own bill, nested under the parent turn. That is how you can see that three helpers cost less than one long parent turn, or the reverse, without opening a provider dashboard.

Scripted runs are honest about what they know: when a model returns no usage, no usage row is invented. The Muse harness is the clearest case in the repository, because its journal carries no token counts at all, so no Usage row is written.

The daily cap

The default is $20 per day across the project. Settings → Safety edits the number and shows today’s ledger beside it. The cap is enforced in two places:

  • Before a turn starts. If the day is already at the cap, the turn is refused rather than started and abandoned halfway.
  • While agents run. Every running agent is interrupted after the step that crosses the cap. The stop is recorded as a budget stop, not as a model error.

At 80% the transcript shows an inline prompt. It is a warning, not a second cap: the turn continues until the real limit is reached.

Preflight

Under the composer’s first-step quote, Rigel shows an estimate for the draft you are about to send. The estimate is the 20th to 80th percentile of the last eight completed turns in this project, scaled to the draft’s size. It is a range because the last eight turns are not a prediction.

  • Fewer than three completed turns: “no history yet”, and no number is invented.
  • Eight or more: the middle band of the last eight, not a lifetime average.
  • The quote is a warning. It never blocks a send.

Reconcile and doctor

rigel doctor reconciles the budget ledger with the session rows and reports a mismatch as a warning or a failure, following the same exit codes as every other check: 0 clear, 1 warnings, 2 failures. That makes a drifted ledger visible in CI instead of only on the Spending page. 

rigel doctor

The window writes the same usage rows the CLI reads. A turn recorded in the window is visible to doctor without an export step.

Limits

  • The provider’s invoice is authoritative. Rigel’s local price fallback is an estimate when a provider omits cost or changes a price after a turn was recorded.
  • The cap is project-wide, not per provider and not per agent.
  • The cap stops Rigel’s turns. It cannot stop a harness you launched outside Rigel.
  • Preflight is a warning based on history. A first turn, or a new model, has no history to scale from.
  • Reconcile fixes the ledger’s view; it does not re-bill a provider.

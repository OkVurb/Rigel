01 — How it works

Index once. Review before you trust. Then let agents work.

  1. 01

    One catalogue, built locally

    rigel skills index anthropics/skills crawls a source, stores bodies in a local blob store and an FTS5 index beside them. Nothing is uploaded, and a second run refreshes from an ETag instead of re-downloading.

  2. 02

    A review with a paper trail

    Six capability rules flag privilege escalation, network egress and destructive commands — each with the file:line that triggered it. A grade says what it covered, so a green row never claims more than it checked.

  3. 03

    Agents that cannot silently collide

    A file claim is advisory, never a lock. When two agents touch one path, the stale side goes to a three-way merge with base, ours and theirs on screen, and the result lands through a CAS journal with an attributed diff.

03 — Features

Built, not planned

Each of these is exercised by tests in the repository — the what-works table says exactly how far each one goes.

Duplicate detection

SimHash clusters near-copies, so twenty forks of one prompt read as one row with a variant list instead of twenty results.

Claims, not locks

A live claim names who is editing what. It never blocks a write — it makes a collision visible before it becomes a lost change.

Three-way merge

Base, ours and theirs rendered side by side; the merged result is editable and writes through the same CAS pipeline as everything else.

Per-agent bill

Usage is recorded per turn and per child agent, so a fan-out shows what each helper cost rather than one number that hides the expensive one.

Writable subagents

A helper gets its own worktree, a claim on each file and a plan you approve. Its work lands only through a merge a clean-context reviewer signed off.

Opt-in cloud sync

Point Rigel at a Firebase project you own and shelf metadata mirrors across machines. Bodies never leave the disk; a deletion travels as a tombstone.

Doctor with an exit code

rigel doctor prints one row per check: 0 clear, 1 warnings, 2 failures. It is meant for CI as much as for your terminal.

A phone reader

Publish one session and the iPhone app reads its prompts and replies from the same project — never tool calls, command output or your project path.

04 — Quick start

From a clean machine

Build the desktop app

git clone https://github.com/OkVurb/Rigel
cd Rigel
cd ui && npm install && npm run build && cd ..
cargo build --workspace
cargo run -p rigel-app

The Tauri shell embeds ui/dist at compile time, so the renderer is built before the workspace.

Or just the CLI

cargo install --path crates/rigel-cli
rigel skills index anthropics/skills --limit 20
rigel skills search "pdf"
rigel doctor

The installer ships MSI and NSIS builds for Windows 10 1809 and newer — no Node, no Python, no Rust needed once installed.

05 — Web app

Read what you published

Sign in with the Firebase project your desktop already syncs to and read the sessions you published — titles, projects, prompts and replies. It is a reader, not a second control surface: it cannot run an agent, and the rules only ever let it see your own documents.

06 — FAQ

Questions worth answering

Does Rigel need the internet?

No. The index, the shelf, the agents and the transcripts are local. The one optional online path is Rigel Cloud, and it stays off until you point it at a Firebase project you own.

What actually leaves the machine?

Nothing, unless you press a button that says so. Push sends shelf metadata — never a body. Publish sends one session's prompts and the assistant's own words — never tool calls, command output or your project path.

Which agents does it run?

Codex, Claude Code, Cursor and Cline through their own CLIs, plus a native coordinator with path-checked tools. Each harness gets its own key, held in the OS keychain.

Windows only?

Windows-first: MSI and NSIS installers for Windows 10 1809 and newer. The core is a Rust workspace and the phone client is iOS; other desktop targets are not a supported surface today.

Is the cloud a subscription?

No. Rigel is a binary you run, and the cloud is your own Firebase project on your own bill — or nothing at all.

Where are the 300,000 skills?

The catalogue holds 11,587 skills measured from public sources. Independent censuses put the entire public universe at roughly 238,000 unique skills, so a larger number would be padding rather than coverage. Every row names its source, and a body is only kept when Rigel fetched it itself.

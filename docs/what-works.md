# What works

This is the long version of the README's summary: every surface in the window and the CLI, its
state, and the reason to believe it. Anything deliberately unfinished is listed as such.

| Surface | State |
|---|---|
| Shelf: search, rows, detail, evidence table, variants | **real**: SQLite FTS5 over `index.db`, offline, `skills.search`/`skills.load` over IPC |
| Shelf: static review | **real**: six capability rules with `file:line` evidence, grade from the same scan the prototype used |
| Shelf: source health | **real**: `ok` / `stale` (with last-sync date) / `broken`, read without a network call |
| Shelf: auto-refresh | **real**: a source older than the stale window is re-synced at launch, off the UI thread, unless the switch is off; Settings → Skill shelf shows each source, refreshes on demand and indexes a repository. `rigel skills refresh` is the same pass, and the two faces share one implementation |
| Shelf: empty state | offers "Index repository" when no source has ever synced |
| Cloud | **real, opt-in**: a Firebase project the user owns — Identity Toolkit email/password sign-in, account creation, password reset and email verification with a send/resend control on the account page (`rigel cloud verify`, `--check`; the refresh token and the verification answer live in the OS keychain, never the renderer, and a reset answer does not reveal whether the account exists), Firestore REST under per-user rules, Push/Pull mirroring shelf metadata while bodies stay local, **deletion tombstones** from a per-account manifest (`cloud-state.json`) with a visible last-push/last-pull clock in Settings → Cloud and `rigel cloud status`, and **Publish to phone** writing one session's prompts and assistant text to `users/{uid}/sessions/{id}/turns` (tool calls, command output and the project path excluded), and optional **Firebase App Check** through a custom provider: `rigel cloud app-check --url` or Settings → Cloud → App Check stores an attestation endpoint, tokens are cached in memory and attached as `X-Firebase-AppCheck` to every Firebase request, and the token provider's contract (token, Unix-second expiry, fail-closed errors) is covered by unit and fake-server tests (`ios/RigelPhone/Tests/RigelRoomKitTests/CloudKitTests.swift` covers the phone's). The iPhone client signs in to the same project and lists/reads those documents, with its decoder covered by `ios/RigelPhone/Tests/RigelRoomKitTests/CloudKitTests.swift`. Exercised end to end against a local stand-in for all three Firebase hosts (`crates/rigel-core/tests/cloud.rs`); **not** exercised against a live Firebase project on this machine, because the repository does not own one |
| GitHub source | **real**: parse `owner/repo` or any GitHub URL, one tree call, raw bodies, ETag cache |
| SkillsMP / SkillHub | **real** via `rigel skills sync`; metadata only, no bodies (they have none to give) |
| Duplicates | **real**: SimHash ≤ 3 bits, clusters computed after every ingest, variants listed under the row |
| Evidence | **real**: advertised percentages from the description, `unmeasured` until a measurement exists, and `audited` for a dated third-party verdict |
| skills.sh import | **real**: `rigel skills import --skills-sh <page>` indexes just that skill's body and stores the page's Gen/Socket/Snyk verdicts as dated evidence rows (`audit:socket=pass`). A verdict never changes Rigel's own grade; a page without an audit section is refused rather than read as a pass |
| CLI | `rigel skills search|get|remove|index|status|sync|sweep|stats|import|gc|refresh`, all with `--json`, §7.2 exit codes; `import --from <file>` for the prototype export, `import --skills-sh <url>` for one skills.sh page. `rigel models [--provider …] [--all]` prints the picker's merged roster (`--all` includes image, video, audio and retrieval rows) |
| Cloud CLI | **real**: `rigel cloud status\|configure\|login\|sign-up\|reset\|logout\|push\|pull\|sync\|publish\|app-check`, each with `--json`; the password and the web API key are read from stdin, the refresh token never leaves the keychain, and the exit codes follow §7.2 |
| Native agent | **real**: OmniRoute (local router, autostarted; default `gpt-5.6-sol-medium`), OpenRouter and Gemini (`gemini-4-argon` by default) streaming with retries, a deterministic scripted model, ten tools with path-checked reads and writes, skills pinned per session |
| Provider adapters | **real**: one table (`crates/rigel-core/src/agent/providers.rs`) behind the chat layer — OmniRoute, OpenRouter, Gemini on AI Studio, **Gemini on Vertex AI** (project and location in the URL, an OAuth access token, `google/gemini-…` ids), **Anthropic** (`claude-…` ids, default `claude-opus-5-5`), and the OpenAI-compatible vendor endpoints (OpenAI, xAI, Groq, DeepSeek, Mistral, Together, Fireworks). The app and the CLI build every turn from the same row, Settings renders that table through `providers_list`, the picker reads each vendor's own `/models` where one is published, and a model id that names a batch endpoint — or another door's namespace — never reaches the wire. Anthropic is the one row whose contract is not `/chat/completions`: `crates/rigel-core/src/agent/anthropic.rs` speaks the Messages API — `Authorization: Bearer`, the system prompt hoisted to a top-level field, a required `max_tokens`, tool results as `tool_result` blocks on a `user` turn, named stream events, and a dated `anthropic-version` on every request including the roster. `temperature` is sent to no other door and is **not** sent here either: API version `2026-10-21` removed the sampling parameters and answers a request carrying one with a 400; effort goes as `output_config.effort` instead of a `thinking` budget, which current models reject. Verified against the platform docs and the vendor endpoints' documented bases; on this machine OmniRoute, OpenRouter, Gemini, OpenAI and Anthropic hold credentials, and the Anthropic one is refused by the provider (`401 invalid x-api-key`), so the adapters are exercised by the unit tests' scripted servers rather than a live turn |
| Model roster | **real**: a stored key is the permission to use a door, so the picker **merges every credentialed provider's roster** (capped at six, current provider first, OpenRouter offered with no key because its list is public) and tags each row with its door; a provider that publishes no roster contributes its own default, labelled as such, and one dead roster is reported rather than emptying the list. `crates/rigel-core/src/agent/catalog.rs` holds it so the window and `rigel models` cannot disagree. Live on this machine: **1 222 rows** — 629 router, 464 OpenRouter, 128 OpenAI, 1 Gemini default — with provider chips, search and a **chat-only filter** in the picker — on by default and saved as `chat_models_only`, so the toggle survives a restart: a row is hidden only when the vendor declares every output non-chat or its id names a non-chat family (phrase-matched, so `dva/inkling-*` survives `kling`), which held back **212 of 1 222** when measured (185 router, 25 OpenAI, 2 OpenRouter); the toggle shows the rest, and `rigel models --all` prints them with a `non-chat` tag. The counts track the vendors' live rosters, so they drift between readings |
| Commands | **real**: `run_command` shows the exact text, cwd and timeout before anything runs; cwd is jailed to the project, output is capped at 64 KB per stream, the process is killed at its timeout, and the exit code is recorded as a `command` item. `--approval ask\|allow\|deny`; `--json` defaults to deny |
| Destructive commands | **real**: a deterministic classifier maps a command to policy rows — `delete-outside-project`, `recursive-remove`, `force-push`, `git-reset`, `registry-write` — before approval; the prompt names the rows and the matched token, and the `command` item records them |
| Snapshots | **real**: before an approved destructive command, `git stash create` object (kept alive by `refs/rigel/snapshots/<id>`) plus raw copies of changed and untracked files; a non-git tree or a repository with no commit is copied whole; 2 000 files / 200 MB cap, refusing above it. `rigel snapshot capture\|list\|restore` |
| Deliberation | **real**: a destructive command first gets one round of three read-only advisors (advocate, opponent, referee) on the parent's model, billed to its own turn and shown before the approval prompt; the answers are advisory and cannot allow, deny or alter the gate. Scripted runs record that advice was not gathered instead of consuming their fixed steps |
| Egress | **real**: `fetch_url` asks per origin with `once` / `session` / `always` scopes (`always` persists in `<index dir>/approved-origins.json`), re-approves a redirect that crosses origins, reads only text-like content types, caps the body at 256 KB, and records the page as a `web_search` item with `untrusted: true` |
| Subagents | **real**: `spawn_agents` starts up to 4 read-only children in the background on an eight-model cheap allowlist (GPT-5/5.4 nano, Gemini Flash-Lite/3 Flash, DeepSeek V4.1 Flash, Qwen3 Coder, Haiku 5.5, GPT-5.4 mini); each child is its own agent row and bill, nested under the parent turn, and must be given a role, an explicit file list and a task. The parent returns at once, can `chat_send`/`chat_wait` with the children in the session room while they run, and collects them with `subagent_results` before finishing. The split is recorded on the session work board, every child sees it and may read only its own files, and each starts its answer with the files it worked on; `assign_agents` gives the same file-scoped work to agents already in the chat room. **Write mode (D80)** gives a child its own worktree, a claim on each assigned file and the full tool set scoped to that list; its work lands only through `merge_subagent`, which reviews the diff with clean context, stores the verdict and merges through the CAS journal. The allowlist is OpenRouter-shaped, so the tool is hidden on the Gemini and Anthropic providers — whose namespaces would replace every id with their own default — rather than handing them ids their endpoints reject |
| Safety defaults | **real**: three writable children at once (D113), a per-child plan the user approves or skips with a reason (D114), a blocking clean-context reviewer on every writable merge with a recorded override (D115), and a $20/day cap across the project that refuses a turn before it starts and interrupts every running agent after the step that crosses it (D116). Settings → Safety edits the cap and the writable count and shows today's ledger |
| The bill | **real**: micro-dollar accounting from provider usage, local price fallback, 80% warning, cap enforced within one turn, `reconcile` |
| Session surface | **real**: roster with a manual `+ agent` form, role-gutter transcript, streaming text, collapsed tool lines, patch diffs, raw/debug toggle, inline 80% prompt, two agent transcripts side by side (a running subagent appears as soon as its turn starts), a live model and effort picker that merges the current provider with OpenRouter's full roster and switches provider with the picked model, and a Swarm button that wakes the room and sends the typed task to the agents you keep ticked |
| Patches | **real**: CAS check, write-ahead journal, fsync + rename, idempotent apply, revert once applied |
| Resume | **real**: tree hash vs checkpoint, running turns closed as `cancelled`, journal reconciled without applying, forced continue is an intervention |
| Memory | **real**: committed `MEMORY.md` + topics per agent, absolute-path/secret validator, index rebuild |
| MCP | **real**: stdio server scoped to `--session` and `--agent`, sharing the same tools |
| Codex harness | **real**: `rigel codex probe` and one turn through `codex app-server`, with `codex exec --json` as the tested fallback; Rigel writes the router `-c` overrides itself (verified against Codex 0.162.1) |
| Claude harness | **real**: `rigel claude probe` and one turn, recorded as a session turn and billed with the CLI's own `total_cost_usd`; the turn passes `--mcp-config` and `--permission-prompt-tool mcp__rigel__rigel_approve`, and the CLI answers each question on stdin with the same four scopes as the native agent. Protocol verified against a scripted 2.1.251 stream; a live subscription turn has not been run. The window sends Claude a turn as well: pick `claude` in the composer and `turn_send` runs the harness, with the approval card answering `rigel_approve` through the app's own `mcp` mode |
| Gemini CLI harness | **real protocol**: `rigel agent acp --harness gemini` drives one ACP turn through `gemini --acp` (the flag replaced `--experimental-acp` in 0.33), records session updates and both sides of every permission request, and takes `GEMINI_API_KEY` — the same keychain entry as the native `gemini` provider. Probed as its own row with the install hint `npm install -g @google/gemini-cli`; verified against the scripted ACP agent, because the CLI is not installed on this machine |
| Cursor/Cline harness | **real protocol**: `rigel agent acp --harness cursor|cline` drives one ACP turn, records session updates and both sides of every permission request, and refuses a subscription-only identity; each harness takes its own key (`CURSOR_API_KEY`, `CLINE_API_KEY`) and is probed separately. An ACP run asks on the CLI's stdin, and the window card is the native agent's surface. Verified against a scripted ACP agent — neither CLI is installed on this machine |
| Claims | **real**: `acquire` / `heartbeat` / `release`, a tombstone on release, staleness reported and never auto-released, 24 h expiry; `rigel claim list\|release`, MCP `rigel_claim` / `rigel_release` / `rigel_who` |
| Attribution | **real**: a 250 ms watcher that hashes changed files, names the writer or marks `ambiguous`, and records a conflict when a claimed path moves under someone else |
| Diff | **real**: conflict strip with both names and hashes, claims with stale rows, unverified counts, per-patch revert, and a comment box per hunk that sends the note back to the hunk's author as a turn (the patch itself is never edited). A conflict expands into its three rendered versions — base, ours, theirs — which merge line by line into an editable file written back through the CAS patch pipeline (D79). A `Subagent worktrees` block lists every writable child with its approved plan and its stored merge verdict (reviewer, reason, diff hash, override — a merge that went over a block is marked), and reads the worktree's pending diff on demand. An unmerged review carries its decision: an approved one merges in one click, a blocked one needs a typed reason that is stored beside the verdict, and neither merges unless the worktree still holds the diff that was judged. A merge decided there is written into the transcript as a note on the parent turn — painted in the user's voice — and the next turn restates it in the preamble, so the parent knows the tree moved |
| Tools and trust | **real**: twelve curated tools probed per host, cached with path and SHA-256; requirements inferred from `allowed-tools` and body commands with their line; the five-factor arithmetic printed by `rigel trust explain`; approval-gated installs with exit code and duration in the ledger; unattended queues; apt shown and refused |
| Doctor | **real**: index and project integrity, schema versions, blob rows vs files, stale claims, budget reconcile, keychain, config age, one row per harness, tool hash pins, unfinished installs, update switch; exit 0/1/2 |
| Window | **real**: closing hides the window to a tray icon instead of quitting, so running agents and PTYs keep working; the tray menu reopens the window or quits and reaps every child. If the tray cannot be built, Close keeps its ordinary meaning |
| Sessions | **real**: the Session pane switches between **Sessions** and **Agents**. The list filters by text and status, hides archived rows behind a toggle, and edits in place — rename (one line, 120 characters, blank returns to the automatic title), pin (pinned rows sort first, before newest-first), archive and restore. Archived rows are never deleted: `session_list` still returns them, the palette still searches them, and they stay resumable. Migration `0012_session_list` adds `pinned_at` and `archived_at`; the three edits are `session_rename` / `session_pin` / `session_archive` |
| Palette | **real**: `Ctrl+K` (or the status-bar button) searches actions, skills, sessions, turns and patches through one core read; a turn jump opens its session and marks the row, a patch jump makes that session active in Diff, and pressing `Ctrl+K` inside the terminal is left to the shell |
| Outline | **real**: a mark per prompt, diff, error and approval, derived from the same rows the transcript renders; the active turn follows scroll, a click centres it, and the rail stays out of the two-pane comparison |
| Bookmarks | **real**: a star on any transcript line and any patch hunk, one list per session in the inspector with jump links, stored in `bookmarks` (migration `0013`); a hunk jump opens Diff on that hunk |
| Composer history and snippets | **real**: Up/Down recalls the project's sent prompts (boundary-aware, `Ctrl+Up` widens), and a project-local snippets menu inserts text with the first placeholder selected; neither ever sends |
| Cost preflight | **real**: the 20th–80th percentile of the last eight completed turns, scaled to the draft, shown under the first-step quote; "no history yet" below three turns; a warning, never a block |
| While you were away | **real**: a dismissible card on focus reports turns finished, patches applied, approvals waiting and spend since the window lost focus; it adds no second notification path |
| Attention | **real**: a rail badge counts every unresolved row — open approvals, failed turns, budget stops, stale claims, unmerged reviews and blocked merges — and the view groups them by session, archived sessions included, with an item opening the turn or the diff that resolves it. The list is read from the ledger and the live approval bus; a retry, release, merge or answer clears the row, and the badge follows within ten seconds. An approval records the project, session, agent and turn its surface knew; the block and the Session card's pending read are scoped to the open project, and a row opens that turn — an older queued question with no origin stays visible and opens the Session card (D154) |
| Provenance | **real**: every diff line and every hunk head opens the recorded chain — hunk ranges, patch, turn, tool, agent and model; a missing link is printed as "unknown" with the reason, never guessed |
| Session templates | **real**: `.rigel/templates.json` holds model, effort, steps, roster and a prompt skeleton per project (atomic write, 40 cap, never committed); `+ session` offers them and "save template" stores the current session's shape. Pinned skills are not in a template yet because the window has no skill-pin surface (D140) |
| Scale and density | **real**: 90/100/110/125% and Roomy/Compact saved in `settings.toml`, applied live; list and inspector widths drag, nudge with Arrow keys and persist per project; the inspector folds away below 1080px |
| Accessibility | **real, window pass**: skip link as the first Tab stop onto a focusable main, labelled turn articles, global `:focus-visible`, reduced-motion rule and a `prefers-contrast: more` palette for both themes; a keyboard-only walk of the full exit test on a real build is still open |
| Updates | **real**: one signed check of the latest GitHub release at launch, an Ed25519 manifest over `version / url / sha256` (plus optional MSI fields), an artifact SHA-256 check, and Settings switches for the check and auto-install (both on by default). The Ed25519 publisher key is not the Authenticode certificate that signs the installers |
| Local services | **real**: the window starts every service a turn can need as it opens — OmniRoute when the provider uses it, and the agentchattr room when its checkout sits beside the restored project. Both run off the UI thread; a service that cannot start is a status in its tab, never a failed launch. A room left running by an earlier window is taken over through the token in its landing page instead of forcing a restart |
| Settings | **real**: thirteen pages over one nav — Agent (model, effort, steps per turn), Providers (one row per adapter, its key, the router), Harnesses (probe plus the four harness keys), Safety, Spending, Terminal (font, scrollback, shell), Appearance, Skill shelf (auto-refresh switch, sources, refresh, index a repository), Cloud (project, account, email verification, App Check, Push/Pull), Project rules, Notifications, Updates, Diagnostics. Every control is saved to the place it belongs — app preferences in `settings.toml`, credentials in the OS keychain, caps in the project database — and every one is read by the core. **Appearance** saves `theme` (`dark` by default, `light` on request) through the same `settings_set` path, and both palettes are measured: on light, the faintest metadata is 4.90:1 on the raised surface, text in the amber hue is 4.71:1, and the terminal swaps to a light ANSI set whose dimmest slot is 4.5:1 — the PTY is not restarted |
| Terminal | **real**: a rail surface backed by a real PTY (`portable-pty`), PowerShell on Windows and `$SHELL` elsewhere, opened in the project root. Font size (10–20), scrollback (1 000–100 000 lines) and the shell program are settings: the first two restyle an open tab in place, the third is read when a tab opens. The surface itself is a framed canvas with a status pane (shell, cwd, state, font) rather than a bare box. xterm.js handles drawing and keys; input, output and resizes cross IPC, the shell survives tab switches, Restart opens a fresh one, and closing the window hides it in the tray with the agents still running; Quit from the tray kills it. Console children spawned by turns and probes are hidden on Windows so no command flashes a black window, and the chat server runs under `pythonw.exe` so the sidecar never opens a terminal |
| Prototype migration | `rigel skills import --from` + [the export snippet](migrating-prototype-index.md) |
| Discover / Targets / Dependencies (prototype) | still the Phase 0 browser app; Phase 6 ports them |

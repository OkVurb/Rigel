# Phase 2 — manual exit test

Run this before ticking P2.11. Everything here is a command you can paste; the "recorded" column is
what the machine that finished Phase 2 actually produced, so a future failure shows up as a
difference rather than as a shrug.

Data directory: use a throwaway one (`RIGEL_INDEX_DIR`) so the numbers are reproducible and your real
index is untouched.

```bash
export RIGEL_INDEX_DIR=/tmp/rigel-p2
cargo build -p rigel-cli --release      # or use the debug binary
R=target/release/rigel                  # C:/rigel-target/release/rigel.exe on Windows with a long path
```

## 1. Cold index of a real repository

```bash
$R skills index anthropics/skills --json
$R skills index affaan-m/ECC --json
```

| Expected | Recorded (20 Oct 2026) |
|---|---|
| Both commands exit 0 and print an `IngestReport` with `with_body == found` | `anthropics/skills`: 20/20, 22 requests, 1.8 s. `affaan-m/ECC`: 500/500 (of 1062 found, `--limit` default), 502 requests, 11 s |
| ECC reports `truncated: false` | `false` |
| Every skill got a grade, a fingerprint and a cluster id | 496 clusters over 520 rows |

A repository with no `SKILL.md` must fail with exit code 2 and a readable message:

```bash
$R skills index octocat/Hello-World --json; echo "exit=$?"
```

## 3. Offline search is fast from a cold start (P2.11)

The point of the dead proxy is that any accidental outbound call fails immediately instead of
silently working because the network happens to be up.

```bash
for i in 1 2 3 4 5; do
  HTTPS_PROXY=http://127.0.0.1:9 HTTP_PROXY=http://127.0.0.1:9 \
    /usr/bin/time -f "%e s" $R skills search code --json --limit 500 > /dev/null
done
```

| Expected | Recorded (7 runs, Python `perf_counter`, Windows) |
|---|---|
| At least 40 results for a broad term over 500+ rows | **58** results for `code` |
| Every run returns in under 50 ms from a cold start | median **30.2 ms**, max **36.3 ms** |
| Results are unchanged with the network unreachable | identical count with `HTTPS_PROXY` pointed at a closed port |

## 6. Sources report stale and broken states (P2.5)

```bash
$R skills sync skillsmp --query pdf --limit 5 --json
$R skills status
$R skills status --json
```

| Expected | Recorded |
|---|---|
| A successful sync marks the source `ok` with `last_sync_at` | `skillsmp ok  last sync 2026-10-21 05:55` |
| A failed fetch marks `broken` and **keeps** the previous `last_sync_at` | `an_unreachable_source_goes_broken_and_keeps_its_last_sync` passes |
| An empty index has no source rows at all, and says so | `rigel skills status` → `no sources yet — rigel skills index <repo>` |
| A source untouched for 24 h reports `stale` | `load_status` derives it from `last_sync_at`; `a_version_1_index_upgrades_to_0002_in_place` and the CLI's own `status` path exercise the same function |

## 7. Bodies are on disk, not in SQLite (P2.3)

```bash
python - <<'PY'
import sqlite3, os
db = os.path.join(os.environ["RIGEL_INDEX_DIR"], "index.db")
c = sqlite3.connect(db)
print(c.execute("SELECT count(*) FROM blobs").fetchone())          # manifest only
print(c.execute("PRAGMA table_info(skills)").fetchall())            # no body column
PY
ls "$RIGEL_INDEX_DIR/blobs" | head -3
$R skills gc --json
```

| Expected | Recorded |
|---|---|
| `blobs` table has no rows; `skills` has no body column | `0` rows, and no `body`/`content` column |
| `blobs/` holds one 64-hex file per distinct body | 521 files, ~6 MB |
| `gc` keeps every body **and** every cached response | first run removed 2 orphans left by an interrupted re-index; the second run `{"live": 520, "removed": 0}` |

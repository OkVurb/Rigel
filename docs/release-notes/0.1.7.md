# Rigel 0.1.7 — quality and release hardening

**4 November 2026 · public unsigned beta**

This is a small, deliberate release. It fixes the Settings gaps found after 0.1.6 and puts the
release process on a hard, documented gate. The substantial round-9 features are recorded for 0.2,
not quietly claimed here.

## What changed

- **Settings repair.** Advanced preferences that had no editable home now do: the composer refinement
  switch lives on Agent, the default session cap lives on Safety, and new sessions read it from
  `settings.toml` instead of a hardcoded `$5.00`. A zero default means no cap. The unused
  `unattended_default` preference is gone.
- **Release gate.** `docs/release-checklist.md` records the required CI, installer, update, install,
  hash and rollback evidence. `docs/grilling-round-9.md` holds all 120 round-9 decisions, and
  `docs/roadmap-0.2.md` holds the deferred work.
- **Supply chain.** Releases now generate and attach a CycloneDX SBOM, and the checklist requires
  Cargo and npm audits before the tag. Both audits are clean: `cargo audit` reports no
  vulnerabilities after `plist`, `quick-xml`, `time` and `tokio` moved past their advisories, and
  `npm audit --omit=dev` reports none. The fixes need Rust 1.88, so the workspace floor moves from
  1.85 to 1.88; nothing else in the build contract changes.
- **Security and privacy.** `SECURITY.md` keeps the threat model and now uses GitHub private
  vulnerability reporting. `docs/privacy.md` describes the actual data flows, and `docs/terms.md`
  states the beta terms.
- **Installer and updater.** The existing MSI/NSIS artifacts, branding gate and Ed25519 update
  manifest are unchanged. Auto-install remains on by default; turning it off keeps the one-click
  offer.

## Install

Download either installer from the release assets:

- `Rigel_0.1.7_x64_en-US.msi`
- `Rigel_0.1.7_x64-setup.exe`

The install is per-user and leaves existing Rigel app data in place. Windows 10 1809 or newer is
required. The installers are **unsigned**, so SmartScreen may warn. The SHA-256 hashes are in the
signed `latest.json` attached to this release.

## Update and rollback

The app checks the signed manifest at launch. With auto-install on, a verified update is downloaded
and started; with it off, the update is offered. Keep the 0.1.6 installer you already have: v0.1.5
and v0.1.6 were never tagged, so there is no earlier release to download. There is no automatic
rollback in 0.1.7; if the new build does not start, reinstall that 0.1.6 build.

## Known limits

- No trusted Authenticode certificate or real Windows 10 1809 VM was available for this cut.
  Windows Sandbox install/start/doctor/uninstall is the clean-machine evidence; 1809 and SmartScreen
  remain manual gaps.
- `cargo audit` still prints warnings without a fix path through Tauri: the unmaintained `unic-*`
  crates and glib's Linux-only unsoundness advisory. Neither is a vulnerability on Windows.
- The very large round-9 surface — hosted Cloud, remote phone approvals, generic forges, SQLCipher,
  full internationalization, native-driver tests, context compaction and the rest — is on the
  [0.2 roadmap](../roadmap-0.2.md).
- The changelog consolidates everything since `v0.1.4`, because `v0.1.5` and `v0.1.6` were never
  tagged.
